# E²-Day 2.1.7 内存对照

同一台 Windows ARM64 主机、相同 .NET 10 Release 构建条件，两个独立新进程及全新的隔离数据目录。基线保留 2.1.6 的界面与图片实现，仅加入相同诊断入口；优化后为 2.1.7。

样例为 24 个已完成任务、24 条完成快照，共用一张确定性生成的 1536×1024 PNG（5,379,656 字节）；普通阶段尚未添加图片。每轮切换今日、历史、概览和全年。诊断阶段等待界面布局并显式收集可回收对象；正常使用不强制 GC、不清空工作集。导航计时不包含诊断 GC，单次测量用于说明此样例，不能外推所有记录和所有电脑。

下表均为 MiB；“私有”指进程私有提交内存，不是 .NET 对象内存，也不是任务管理器的所有内存列。WPF、图形与运行时缓存仍可能随使用增长；本次没有宣称消除所有增长。

新增验证覆盖：缓存命中与 LRU 淘汰、字节与条目上限、PNG 原始数组可回收、长图尺寸上限、像素与冻结状态、点击读取原图、服务修订号失效、旧概览选择器可回收及卡片不再使用整卡 Effect。全部使用隔离数据与记录剪贴板后端。

开发者复现：先构建 Release，再运行 DailyRecord.exe --data-dir <隔离目录> --memory-test <报告目录>。该诊断必须显式指定数据目录，并始终在其下建立全新的 memory-fixture 随机目录；不会打开现有账号。基线构建仅回填 App.xaml.cs 的 --memory-test 入口及 MemorySmokeTest.cs，不带入缩略图或卡片优化。对照时保持主机、架构、窗口大小和样例一致。
